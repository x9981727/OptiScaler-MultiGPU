# RDNA4 r6.2 — 神經網路輸出貢獻驗證

自動選擇名稱含 9070 的顯卡，不會改在 6600 XT 執行 gfx1201 程式。
結果：`rdna4-r62-result.json`、`rdna4-r62-console.txt`。成功或失敗都保留。

本包不含原 checkpoint、原版 runtime、模型權重或 AMD 驅動。

## r6.1 實測已確認的事

三組原版／Head 替換對照一致，最後邊界探測及七輪插樁計時完成。
最後一層保持原參數時，改動 allocation26、allocation5 的兩種圖樣都未改變 allocation2；改動來源 allocation1，輸出差異分別為 13,204,618 及 8,236,521 bytes。
最終參數中的 byte136 為 float32 0，byte140 為 0，byte144 為 uint32 1。
這些是指定測試的觀察，不是所有遊戲或原版 runtime 的通用結論。

## 這版驗證的假說

固定原始 ISA 在 offset0x88 載入 s12–s14；之後輸出區域有 s12 與神經網路值的乘加，再與來源 RGB 路徑合成。這支持「byte136 是該路徑的網路輸出貢獻係數」的假說。

**零值可能讓完整網路照常計算，但它對最後輸出的貢獻被歸零。**
本版要以 GPU 控制實驗驗證這件事，不能只從片段反組譯就當成已證明，也不能把跳過網路造成的巨大 FPS 增幅當成正確加速。
這個欄位的官方名稱、遊戲中正確值，以及完整主機端控制綁定尚未確定。

## 與先前版本的關鍵差別

以前不改參數；本版會**明確且暫時**變動測試行程記憶體中「最後命令157、唯一168-byte參數、byte136–139」的四個位元組。
原 checkpoint 檔仍照原 SHA256 驗證，不會改寫或重新命名為通過版。原版零值基準保留。

預先固定的實驗值為 0、1/32、1/8、1。不是遊戲設定建議；也不會寫入遊戲設定。
其他參數位元組、指標、模型權重、呼叫順序和幾何配置保持不變。
操作前同步 GPU；結束／例外離開時還原參數。正常完成還會重跑原始零值計畫，逐位元組核對所有配置已還原。

每個相同控制值下，原版與兩種 r4 Head 替換版都使用相同的輸入與初始化，核對全部配置、Head 前後張量及保護區。三者不是拿不同畫質參數相互比速度。
再使用两組不同的有限 FP8 Head 輸出改動，各重複兩次，檢查差異是否真正到達最後觀察區域。
另外以 CPU 的指定輸出公式比較原始零值輸出，保存是否逐位元組相符，而不是因為看起來一樣就推定是來源 RGB 複製。

變動輸入案例測四種係數；固定輸入案例另測 0 與 1/32，共六個完整計畫測試設定。

## 計時條件

只在預先指定的「變動輸入、係數1/32」通過兩組敏感性測試後，才進行45輪前段＋21輪保留樣本的完整 GPU graph 比較。
每個版本都使用同一係數1/32。包含全部154次核心呼叫和4次原版GPU複製；不含前置狀態重設與上傳。
不根據哪個係數最快來選值，不把原始零值與非零模型輸出混在一起比效能。
所有原始時間、HIP回傳碼與數值位元保存。未解析或異常樣本不得被換成epsilon或刪除以製造加速。
沒有鎖定時脈、量測功耗或真實遊戲時序；這些時間不是遊戲FPS。

若1/32未通過敏感性，跳過這組計時，仍繼續其他有界控制探測；不擅自放寬發布門檻。

## 狀態解讀

`experimental_gain_restores_neural_sensitivity_not_game_validation`：本次原始零值基準仍不敏感，且已測的非零控制案例在兩組Head干預下都敏感。這只支持本次控制假說，不代表遊戲正確值已找到。
`control_experiment_complete_hypothesis_not_fully_confirmed`：流程完成，但假說沒有全部吻合；查看各實驗結果。
`failed`：保存錯誤紀錄，不要把測試包接入遊戲。

無論哪個狀態，`release_gate.approved`、`full_model_quality_verified`、`game_tested`、`game_deployment_approved` 仍為 false。
即使非零設定通過，也不會把原本失敗的零值敏感性偷偷改為通過。
